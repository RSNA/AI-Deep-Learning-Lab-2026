## Overview

This year, Lab 02 is a game. You will not write or run any code.

AI coding tools can now write much of the code behind an agentic application. The harder questions are whether a radiology problem needs an agent in the first place, how to design a system that fits the clinical workflow, and how to keep that system safe after it goes live. These decisions rest with the people who know the practice, and they are the focus of this session.

Every participant takes the role of the AI director of a simulated radiology practice and plays in the same live session as everyone else in the room. The game has three phases:

1. **Planning.** Investigate your practice, find its real problems, and decide which ones call for an agentic system and which are better served by something simpler.
2. **Development.** Design an agentic solution by combining agents, conventional models, rules, tools, and human checkpoints. Pilot it, read the results, and improve it.
3. **Maintaining.** Keep the system working over time as models are updated, data shift, and unexpected failures appear.

A short discussion follows each phase, and a live leaderboard runs throughout.

If you are new to AI agents, we recommend attending [Lab 01: A Low-Code Introduction to AI Agents in Radiology](../01-Low-Code-Introduction-to-AI-Agents/) earlier the same day. This session opens with a brief recap of the core concepts.

## Learning Objectives

By the end of this session, participants will be able to:

1. Decide which radiology problems call for an agentic system and which are better served by simple software, a single-task model, or a language model alone.
2. Design an agentic workflow that combines agents, conventional models, rules, tools, and human checkpoints, with appropriate data access and supervision.
3. Evaluate an agentic design for validity, reliability, cost, and complexity before it is deployed.
4. Maintain a deployed agentic system by monitoring for drift and silent failures and by responding to model updates.
